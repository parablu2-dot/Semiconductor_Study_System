## Windows·서브프로세스 환경 버그
Windows에서 `subprocess.run(shell=True, timeout=...)`을 쓰면 타임아웃 시 표준 라이브러리가 최상위 `cmd.exe`만 죽이고 그 자식(`claude.cmd`→`claude.exe`)은 orphan으로 남는다. 같은 종류의 함정(PATH에 도구 번들을 추가하면 그 안의 실행파일이 시스템 것을 shadow)이 세션을 달리하며 반복 재발했다 — 한 번 고친 환경 버그도 다른 맥락에서 다시 걸릴 수 있다는 교훈.

### S46 Windows subprocess orphan claude.exe 버그 근본 수정
shell=True + timeout 조합에서 kill()이 최상위 cmd.exe만 죽이고 자식 claude.cmd가 orphan으로 남는 구조적 버그를 근본 수정했다.  
**반복 패턴**: Windows subprocess kill()이 자식 프로세스까지 안 죽이는 구조적 함정  
**원문**: Dave @a5afb09

### S86 i2c_slave_burst B조(timeout 2배) 재현 10회 + PATH 환경버그 재발견/수정
S38에서 이미 한 번 고쳐졌던 DLL_NOT_FOUND 버그(oss-cad-suite/lib PATH 누락)가 재발한 것을 발견해 다시 고쳤다.  
**반복 패턴**: 이미 고친 환경 버그가 다른 세션 맥락에서 재발 — 수정을 영구화할 장치 필요  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

## 자동화 훅 버그
세션 종료 시 기술 용어집을 자동 갱신하는 SessionEnd 훅을 만들었으나, 프로젝트 루트 판정 조건이 좁아 여러 세션 동안 조용히 실행되지 않았다. 자동화 훅은 실패해도 겉으로 드러나지 않으므로, 도입 직후 end-to-end로 실제 실행 여부를 확인하는 습관이 필요하다는 것을 두 번에 걸쳐 배웠다.

### S47 SessionEnd 훅 — 세션 종료 시 용어집 자동 갱신
세션에서 새로 등장한 기술 용어를 자동으로 용어집에 덧붙이는 SessionEnd 훅을 구성했다.  
**원문**: Dave @0185e84

### S60 용어집 SessionEnd 훅 미실행 버그 근본 수정
S47의 훅이 S48부터 12개 세션 내내 한 번도 실행되지 않았음을 발견 — 프로젝트 루트가 저장소 자체일 때만 로드되는 설정 스코프 문제였다.  
**반복 패턴**: 자동화 훅이 조용히 실행되지 않아도 겉으로는 드러나지 않음  
**원문**: Dave @925ce14
