이 프로젝트의 본체 — spec.json에서 실제 RTL을 생성해 표준 주변장치 15개를 만들고, PicoRV32 코어와 함께 하나의 버스(soc_top)로 통합한 뒤, ss 코너 타이밍 문제에 대응해 코어 파라미터·리타이밍까지 손댄 과정. 37개 세션으로 이 프로젝트에서 가장 많은 비중을 차지한다.

## RTL 생성 자동화·폐루프
'spec.json → RTL' 생성도 같은 방식(로컬 CLI 호출)으로 자동화한 뒤, `interpret_spec.py → generate_rtl.py → validate_generated_rtl.py`를 한 커맨드로 잇는 `run_full_loop.py`로 '자연어 요구 문장 하나 → 검증까지 끝난 RTL'이 사람 개입 없이 한 번에 도는 폐루프를 완성했다. 이 프로젝트가 처음부터 목표로 한 핵심 고리다.

### S7 RTL 생성기 자동화
'spec.json → RTL' 생성도 같은 방식으로 자동화해, 자연어→RTL 전체가 LLM 호출 두 번으로 끝나게 됐다.  
**원문**: Dave @bfec66f

### S8 폐루프 오케스트레이션
interpret_spec → generate_rtl → validate를 한 커맨드로 잇는 run_full_loop.py로 '자연어 요구 → 검증까지' 완전 자동화를 완결했다.  
**원문**: Dave @29d41bb

## 표준 주변장치 모듈 생성
타이머·UART·FIFO·인터럽트 컨트롤러·PWM·WDT·I2C 마스터/슬레이브(+멀티바이트)·다중 인스턴스·SPI 슬레이브·CDC 브리지까지 15개 모듈을 순서대로 생성했다. 매번 이전에 없던 구조 패턴(읽기 부작용 `re`, 양방향 포트, 리액티브 FSM, 1-대-N/N-대-1 배선, 2클럭 CDC)을 하나씩 새로 다루며 스펙 스키마와 생성 규칙(v2→v16+)을 계속 확장했고, 뒤로 갈수록 제로샷 성공률이 올라갔다.

### S9 2번째 모듈: 타이머/카운터
스스로 값이 바뀌는 다운카운터 패턴을 다루기 위해 스펙/생성 규칙을 v2로 확장했다.  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

### S10 3번째 모듈: UART 송신부
시리얼 FSM이라는 새 인터페이스 모양에 맞춰, 이번엔 사람이 먼저 레지스터 맵을 확정한 뒤 RTL 생성을 자동화했다(rtl-generator v3).  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

### S12 5번째 모듈: 동기식 FIFO
단일 레지스터가 아닌 메모리 배열 저장소와 읽기 부작용(re) 신호를 처음 다뤘다 — 제로샷 성공.  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

### S13 6번째 모듈: 인터럽트 컨트롤러
여러 인터럽트 소스를 모으는 N-대-1 집계 구조 — 제로샷 성공.  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

### S15 7번째 모듈: 다중 채널 PWM 생성기
카운터 하나를 여러 채널이 구독하는 1-대-N 구조 — RTL 생성과 자연어 템플릿을 같은 라운드에 마쳤다.  
**원문**: Dave @ac9e5c7

### S16 8번째 모듈: 워치독 타이머
타이머의 다운카운터 골격에 물리 리셋 펄스와 '쓰기 자체가 트리거'인 KICK 레지스터를 더해 표준 주변장치 10종을 채웠다.  
**원문**: Dave @e9fef0a

### S18 9번째 모듈: I2C 마스터
SDA 3포트(o/oe/i) 양방향 신호와 7단계 FSM을 다룬 최초의 양방향 포트 모듈 — 싱글 마스터·7비트 주소·1바이트로 범위를 좁혔다.  
**원문**: Dave @00bd420

### S19 10번째 모듈: 다중 인스턴스(듀얼 GPIO)
새 프로토콜 발명 대신 기존 gpio.v를 그대로 2번 인스턴스화해 위험도를 낮췄다 — 표준 주변장치 10종 완성.  
**원문**: Dave @16fc0e8

### S20 11번째 모듈: I2C 슬레이브
자체 클럭 없이 외부 SCL/SDA에 반응만 하는 최초의 순수 리액티브 FSM.  
**원문**: Dave @2f8991a

### S21 12번째 모듈: I2C 마스터 멀티바이트 확장
검증된 i2c_master는 무수정, 새 확장 필드(i2c_master_burst)로 멀티바이트 전송을 추가했다(LEN=1이면 완전한 상위 호환).  
**원문**: Dave @c0beaf2

### S24 13번째 모듈: I2C 슬레이브 멀티바이트 확장
i2c_slave는 무수정, 클럭 스트레칭이 없어 ACK/NACK·STOP만으로 멀티바이트를 처리하는 i2c_slave_burst를 추가했다.  
**원문**: Dave @af4cd05

### S26 14번째 모듈: SPI 슬레이브
풀-듀플렉스(SPI 마스터)+자체클럭없음(I2C 슬레이브)의 교집합 — 가장 단순한 리액티브 FSM으로 완성.  
**원문**: Dave @bbc873e

### S28 15번째 모듈: 클럭 도메인 교차 브리지 cdc_sync
두 번째 자유구동 클럭(aux_clk)을 다루는 최초의 모듈 — 2단 동기화+엣지검출과 토글 핸드셰이크 두 CDC 기법을 각각 구현했다.  
**원문**: Dave @cce3930

## 코어 파라미터 구성
새 RTL을 생성하는 대신, Stage 0에서 이미 검증·고정한 `picorv32.v`(무수정)의 파라미터 조합을 자연어로부터 제안하고 얇은 래퍼로 인스턴스화하는, 지금까지와 다른 성격의 트랙을 열었다.

### S17 PicoRV32 파라미터 구성 제안 자동화
새 RTL을 생성하는 대신, 이미 검증·고정한 picorv32.v의 파라미터 조합을 자연어로부터 제안하는 트랙을 열었다.  
**원문**: Dave @f0349f7

## soc_top 통합(MMIO 조립)
검증된 15개 모듈을 하나의 버스(PicoRV32 MMIO)로 묶는 축 — RTL을 새로 생성하지 않고 기존 모듈을 그대로 인스턴스화 + 디코더만 확장하는 방식으로, gpio/timer/uart_tx 3개에서 시작해 14개 표준 주변장치 + cdc_sync + uart_rx(16개)까지, 그리고 인터럽트 실배선까지 마쳤다. 모듈마다 새 버스 패턴(읽기 부작용, 외부 입력 핀, 5비트 서브주소, 양방향 SDA)이 하나씩 추가됐다.

### S30 soc_top 최초 조립: PicoRV32 + gpio/timer/uart_tx
15개 모듈이 전부 폐루프 완결된 상태에서 '여러 모듈을 하나의 버스로 묶기'라는 새 구조 축(3단계 SoC 조립)에 처음 착수했다.  
**원문**: Dave @2f4b585

### S31 soc_top에 5번째 모듈 추가: spi_master
spi_master를 오프셋 0x30에 추가 — 기존 버스 관례라 디코더 확장이 최소한으로 끝났다.  
**원문**: Dave @eeecb91

### S32 soc_top에 6번째 모듈 추가: pwm_gen
STATUS 폴링이 없는 순수 조합 출력 모듈이라는 첫 사례 — 검증 방식을 새로 설계했다.  
**원문**: Dave @2f89a9e

### S33 soc_top에 7번째 모듈 추가: wdt
write-only KICK 레지스터와 1클럭 폭 리셋 펄스라는 두 새 패턴을 다뤘다.  
**원문**: Dave @425b996

### S34 soc_top에 8번째 모듈 추가: sync_fifo
읽기 자체가 부작용(pop)을 일으키는 re 신호를 버스에 처음 배선했다.  
**원문**: Dave @4bcd44c

### S35 soc_top에 9번째 모듈 추가: spi_slave
soc_top 최상위에 진짜 외부 입력 핀이 필요한 최초의 모듈 — 타이밍 동기화가 핵심 난제였다.  
**원문**: Dave @ce14632

### S36 soc_top에 10번째 모듈 추가: irq_ctrl

**원문**: Dave @3c140eb

## 코어 파라미터·PPA 개선
ss 코너 타이밍 문제(d5)에 대응해 미사용 카운터 제거, ALU/비교 2사이클 파이프라이닝, PC 경로 리타이밍(코어 본체 최초 수정)까지 여러 라운드의 RTL 개선을 시도했다. 개선의 실제 효과는 PnR 다이 면적 산정 방식에 크게 좌우된다는 것이 나중(d5 DIE_AREA 스윕)에 드러난다.

### S62 ENABLE_COUNTERS64=0 — 미사용 64비트 카운터 제거
펌웨어가 안 쓰는 rdcycleh/rdinstrh 경로(ss 코너 위반의 12%)를 파라미터 하나로 제거했다.  
**원문**: Dave @c8827c5

### S66 mem_rdata 리드먹스 OR-트리 재구성 — 등가검사 크래시로 미검증 보류
ss 코너 최악경로 24단 체인의 진짜 정체가 PicoRV32 구조가 아니라 soc_top의 14단 선형 우선순위 리드먹스였음을 게이트 단위로 확인, OR-트리로 재구성했다.  
**반복 패턴**: 이전 세션 진단(S59)이 틀렸음을 게이트 단위 직접 확인으로 정정  
**원문**: Dave @0e0fe45

### S69 TWO_CYCLE_ALU/COMPARE — PC/ALU 임계경로 실개선 시도
코어 본체 재설계 대신 공식 지원 파이프라이닝 스위치를 켜 긴 조합 체인을 레지스터 경계로 끊었다.  
**원문**: Dave @a487721

### S72 ENABLE_COUNTERS=0 + TWO_CYCLE 되돌림 — S71 근거 반영
S71 결과를 반영해 파라미터 3개를 조정, 셀 수를 추가로 줄였다.  
**원문**: Dave @bf6f3b8

### S75 코어 config를 S68 기준선으로 되돌림
재설계 착수 전, 실측으로 확인된 최선 상태(S68)를 명확한 출발점으로 재확정했다.  
**원문**: Dave @b3c789d

### S77 reg_pc_plus4 리타이밍 실반영 — 코어 본체 최초 수정
third_party/picorv32/picorv32.v를 이 프로젝트에서 처음으로 직접 수정해 PC 경로를 리타이밍했다.
