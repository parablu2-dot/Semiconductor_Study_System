시뮬레이션과 게이트 레벨 검증을 다 통과한 RTL이 실제 iCESugar(iCE40UP5K) 보드 위에서 정말로 동작하는지 확인하는 축. 비트스트림 재현성 검증부터, 실물에서만 드러나는 배선·빌드스크립트 버그 사냥, AP4의 재부팅 하드웨어 잠금 문제까지 — 시뮬레이션만으로는 절대 잡히지 않는 종류의 문제들이 여기 모여 있다.

## PCF·PnR·비트스트림
`soc_top`은 포트 수가 SG48 패키지의 가용 IO를 넘어서, 의미 있게 연결 가능한 최소 서브셋만 노출하는 새 최상위 래퍼와 4KB 온칩 RAM을 설계해 iCESugar용 PnR·비트스트림 dry run을 성공시켰다.

### S84 iCESugar PCF 확보 + nextpnr-ice40 PnR + 비트스트림 dry run
60개+ 포트를 SG48 패키지 가용 IO에 맞게 최소 서브셋으로 노출하는 새 최상위 icesugar_top.v를 만들고 4KB 온칩 RAM을 새로 설계했다.  
**원문**: Dave @c8d6109

## 비트스트림 재현성·핀 확장 검토
산출물이 byte-for-byte 결정론적으로 재현되는지 SHA-256으로 검증하고, 남은 핀 여유(실질 22개)를 세어 향후 주변장치 확장 가능성만 사전 검토했다(실제 배선은 하지 않음).

### S92 Track A 비트스트림 재현성(byte-for-byte) 검증
S84 산출물을 독립적으로 두 번 빌드해 SHA-256으로 완전히 동일함을 확인했다.  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

### S93 물리 핀 미배선 주변장치 확장 가능성 검토 (RTL 미반영)
PCF 여유 핀을 정확히 세어 실질 가용치 22개를 확인 — 실제 배선은 하지 않은 사전 검토.  
**원문**: Dave @3f932d3

## 실물 부팅·배선 버그
실물 보드에서 두 차례에 걸쳐 '논리 버그처럼 보이는 배선/빌드스크립트 문제'를 만났다 — 처음엔 RGB LED가 파란색 고정으로 보여 부팅 실패를 의심했으나 실제 원인은 특정 핀이 일반 GPIO가 아닌 RGB 드라이버 전용 패드였던 것, 두 번째는 모든 RTL·펌웨어를 배제해도 재현돼 결국 빌드 스크립트 자체의 문제로 판명났다. 둘 다 시뮬레이션 3단 대조나 체계적 배제 같은 실측 기반 절차로 풀었다.

### S94 iCESugar 실물 보드 최초 부팅 확인 + RGB LED 드라이버 버그 수정
RGB LED가 파란색 고정으로 보여 부팅 실패를 의심했으나, 핀 39/40/41이 SB_RGBA_DRV 전용 패드였다는 배선 문제였음을 시뮬레이션 3단 대조로 규명했다.  
**반복 패턴**: 환경/배선 문제를 논리(부팅 실패) 버그로 오인  
**원문**: Dave @31c0c97

### S105 RGB LED '빨강+파랑 고정' 버그 사냥 — 진짜 원인은 build_bitstream.sh
RTL·펌웨어를 전부 배제한 뒤에도 재현돼, 결국 빌드 스크립트 자체의 문제였음을 체계적 배제로 규명했다.  
**반복 패턴**: 환경/배선/빌드스크립트 문제를 RTL 로직 버그로 오인 — 산출물 diff로 검증 필요  
**원문**: Dave (커밋 미태깅 세션 — README/프로젝트 기록 기준)

## UART 물리 루프백
USB-TTL 어댑터 없이 점퍼선 하나(핀4-핀6 직결)로 uart_tx→uart_rx 왕복을 실보드에서 자체판정하는 최소 검증법을 썼다.

### S104 UART 물리 루프백 자체판정 — 점퍼선 실보드 검증
핀4-핀6 점퍼선만으로 uart_tx→uart_rx 왕복을 실보드에서 검증, COM4는 soc_top UART와 무관함을 확인했다.  
**원문**: Dave @bb6ef10

## AP4 실보드 검증
Timer+WDT 데모의 실보드 검증에서 재부팅 시 피드백이 잠기는 현상을 발견했으나 원인을 확정하지 못해 이월했고, 다음 세션에서 이전 가설을 RTL 구조 분석으로 반증한 뒤 진짜 원인을 규명·수정해 재검증까지 완료했다.

### S110 AP4 실보드 검증 — 재부팅 피드백 하드웨어 잠금 발견 (미해결)
재부팅 시 피드백이 잠기는 현상을 발견했으나 이 세션에서는 원인을 확정하지 못하고 다음 세션으로 이월했다.  
**원문**: Dave @7d253e3

### S111 AP4 근본 원인 규명 + 수정 + 실보드 재검증 완료
S110의 'AND-리덕션 글리치' 가설을 RTL 구조 분석으로 반증하고 실제 원인을 규명·수정, 실보드 재검증까지 완료했다.  
**반복 패턴**: 이전 세션 가설(S110)을 RTL 구조 직접 분석으로 반증  
**원문**: Dave @61672d4
