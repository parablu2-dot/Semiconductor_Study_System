"검증됐다"는 말의 층위를 넓혀 온 축 — 기능 검증(cocotb)만으로는 "합성 결과가 원본과 논리적으로 동일하다"를 보장하지 못한다는 빈틈을 형식 등가검사(eqy)로 채웠고, 가장 복잡한 리액티브 FSM의 재현 불안정성을 수십 회 실험으로 정량화했다. 검증 도구 자체의 버그(Windows 스택 오버플로, eqy 파티션 크래시)를 잡아낸 세션도 여럿이다.

## 코어 기능검증
새 RTL 생성이 아니라 이미 벤더링된 `picorv32.v`(무수정)의 인터럽트 경로를 손으로 짠 RISC-V 어셈블리 펌웨어로 기능 검증했다.

### S22 PicoRV32 인터럽트 경로 기능 시뮬레이션
ENABLE_IRQ 경로(getq/setq/retirq 등)를 손으로 짠 RISC-V 어셈블리로 기능 검증했다 — RTL 생성이 아닌 벤더링된 코어 자체 검증.  
**원문**: Dave @8a62f64

## 검증 스크립트·환경 방어
검증 스크립트 자체가 Windows 환경에서 도구 종료 방식을 오판정하지 않도록 방어 로직을 추가했다 — RTL 버그가 아니라 검증 파이프라인 자체의 견고성 문제.

### S23 검증 스크립트에 Windows vvp 종료 크래시 방어 추가
validate_generated_rtl.py가 Windows에서 vvp 종료 시 크래시를 오판정하지 않도록 방어 로직을 추가했다.  
**반복 패턴**: Windows 서브프로세스 종료 처리를 로직 버그로 오인하기 쉬움  
**원문**: Dave @e1b62e4

## 인스턴스 일반화 검증
다중 인스턴스 패턴(2개, d2)이 3개 이상에서도 그대로 일반화되는지 1회성으로 확인한 순수 검증 세션.

### S25 instance_array 3-인스턴스 일반화 검증
다중 인스턴스 패턴(S19)이 2개를 넘어 3개에서도 일반화되는지 triple_gpio로 1회성 검증했다.  
**원문**: Dave @97daf15

## 형식 등가검사(eqy)
'합성이 성공했다'와 '합성 결과가 원본과 논리적으로 동일하다'는 다른 주장이라는 빈틈을 채우는 4번째 검증 게이트를 도입했다. gpio 1개 파일럿(rename 스크립트가 비동기 리셋 DFF를 놓치는 버그 발견) → 14개 모듈 전체 → soc_top 전체(Windows 스택 오버플로 → WSL 이전 → gold/gate 메모리 비대칭 수정 → PASS) → CI 자동 연결까지 확장했고, 이후 코어 파라미터·RTL이 바뀔 때마다(d2 PPA 개선, d5 sign-off) 재실행해 회귀를 지켰다. 도중 eqy 자체의 `bind` 파티션 크래시를 gdb+core dump로 근본 수정한 것도 이 축에서 나왔다.

### S42 4번째 검증 게이트 신설: 형식 등가검사(eqy)
'합성 성공'과 '합성 결과가 원본과 논리적으로 동일'은 다른 주장이라는 빈틈을, gpio 1개 모듈 파일럿으로 채웠다.  
**원문**: Dave @4f5d4d2

### S43 형식 등가검사를 나머지 14개 모듈로 확장

## i2c_slave_burst 재현성 실험
가장 복잡한 다상태 리액티브 FSM(`i2c_slave_burst`)의 '자연어 → RTL' 자동 생성이 확률적으로 얼마나 불안정한지를 누적 수십 회 재현으로 정량화했다. 실패의 상당수가 RTL 로직이 아니라 PATH 환경 함정(같은 종류의 버그가 여러 세션에 걸쳐 재발)이었다는 것을 교란변수 분리로 확인해, 최종 baseline 성공률(약 60%)을 확정했다.

### S50 i2c_slave_burst 재현 13회 전부 실패 + 실패로그 자동기록 정책
복잡한 다상태 리액티브 FSM은 LLM 호출이 확률적으로 실패한다는 것을 13회 전부 실패로 재확인, 실패를 자동 기록하는 정책을 신설했다.  
**반복 패턴**: LLM 기반 RTL 생성의 재현 불안정성 — 복잡한 리액티브 FSM일수록 실패율 상승  
**원문**: Dave @a7367ab

### S52 i2c_slave_burst 재현 이어감 — 새 환경 함정 해결
oss-cad-suite bin을 PATH에 더하면 번들 파이썬이 시스템 python3를 shadow하는 함정을 발견·해결(cocotb는 항상 시스템 파이썬으로 고정 호출).  
**반복 패턴**: PATH에 도구 번들 bin을 추가하면 그 안의 파이썬이 시스템 파이썬을 shadow  
**원문**: Dave @f0d4a4c

### S54 i2c_slave_burst 재현 이어감 (누적 19회, 성공 1회)
S52의 PATH 해법을 그대로 적용해 재발 없이 4회 추가 시도했다.  
**원문**: Dave @66a2fbb
