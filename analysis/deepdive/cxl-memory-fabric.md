# CXL 메모리 페이브릭

## 1. 현재 표준(후보) — 메모리 병목 해소를 겨냥한 fabric 재설계

CXL(Compute Express Link) 3.x(2022~)는 노드·클러스터 사이의 메모리·통신을 재설계하는 대안이다. switch·pooling·sharing을 통해 GPU·CPU·메모리를 한 fabric으로 묶어, [[mfu-utilization-gap]]에서 다룬 이론-실측 격차의 원인 중 하나인 메모리 병목을 해소하려 한다.

CXL은 [[von-neumann-cache-hierarchy]]가 전제하는 flat cache coherence 모델을 확장하는 방향이 아니라, 명시적으로 계층화된 메모리 스코프(로컬 DRAM, CXL-attached pooled memory, 원격 노드 메모리)를 노출하는 방향으로 진화한다는 점에서 [[von-neumann-cache-hierarchy]]의 은폐 전략과는 다른 철학을 취한다.

## 2. 한계 — 표준 성숙과 소프트웨어 활용의 시차

미해결 문제는 표준 성숙과 스위치 하드웨어의 상용화가 여전히 진행 중이라는 것과, 소프트웨어 스택(OS의 메모리 관리·페이지 마이그레이션)이 CXL 3.x가 정의하는 계층 구조를 제대로 활용하는 시점은 아직 남아 있다는 것이다. **하이퍼스케일러 채택 시점에 대한 논쟁이 크다.**

이는 하드웨어 표준(물리·프로토콜 계층)이 먼저 성숙하고 소프트웨어 활용(OS·런타임의 인식)이 뒤따르는, [[chiplet-ucie]]에서도 나타난 것과 같은 패턴의 시차다 — 사양 공개와 실질 활용 사이의 간극이 CXL에서도 반복된다.

## 3. 대안 후보

**분산 학습 프레임워크와의 결합.** [[distributed-training-framework]]에서 다룬 파라미터 shard 방식의 대안으로, 메모리를 GPU 간에 명시적으로 공유·풀링해 shard 자체의 필요성을 줄이려는 접근이 근본적으로 다른 방향을 제시한다.

**독점 인터커넥트(NVLink 등)와의 경쟁.** NVIDIA NVLink·NVSwitch처럼 벤더 종속적이지만 이미 성숙한 인터커넥트와 CXL이 어느 영역에서 경쟁·공존할지는 **논쟁 중**이다 — GPU-GPU 구간은 NVLink가, CPU-메모리-가속기 확장은 CXL이 각자 우세한 영역을 가질 것이라는 절충적 시나리오가 현재 통설에 가깝다.

**소프트웨어 계층의 자동 페이지 마이그레이션 성숙.** OS·런타임이 계층화된 메모리 스코프를 자동으로 활용하도록 하는 연구가 진행 중이지만, 아직 수작업 최적화가 필요한 초기 단계다.

## 4. 교차 계층 영향

**ch6(아키텍처) 관점 — 명시적 메모리 스코프 노출.** CUDA류 명시 스코프, HBM-PIM류 니어메모리와 함께, CXL류 계층 확장 메모리가 마이크로아키텍처의 새 계층을 노출한다. 이는 [[von-neumann-cache-hierarchy]]가 채택한 은폐 전략에 대한 부분적 이탈이며, 프로그래머·컴파일러가 메모리 계층을 인식해야 하는 부담이 다시 늘어난다는 트레이드오프가 있다.

**ch7(패키징·집적) 관점 — D2D 프로토콜 인지 강제.** 마이크로아키텍처가 이 새 계층을 노출하면, 패키지는 그 계층을 물리적으로 실현할 자리(CXL 확장을 위한 신호 경로)를 미리 확보해야 한다. 패키지 플로어플랜이 아키텍처의 메모리 계층 결정에 종속되어 설계 시점에 고정되며, 세대 간 메모리 계층 변경은 패키지 재설계를 유발한다.

**ch8(시스템·SW) 관점 — 되돌아가는 요구.** 분산 학습의 파라미터 관리, LLM 서빙의 KV 캐시 확장 요구가 CXL fabric의 조기 성숙을 요구하는 최상단에 위치한다 — 이 요구가 실제로 아래 계층(패키징·회로)을 움직이는 속도는 하이퍼스케일러의 자본 지출 규모에 달려 있다는 것이 `00_종합.md`가 지적한 사슬 전체의 결론과 같은 패턴이다.
