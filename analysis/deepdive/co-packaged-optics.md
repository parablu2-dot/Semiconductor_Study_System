# Co-Packaged Optics (CPO)

## 1. 현재 표준(후보) — 스위치에서 시작된 pJ/bit 절감

Co-packaged optics(CPO)는 광 트랜시버 다이를 로직 옆에 같은 패키지 안에 배치해 pluggable optics의 소비 전력·pJ/bit을 크게 낮추는 방향이다. Broadcom·Marvell·Cisco 등이 스위치 SoC에서 초기 상용을 시도했다.

이는 [[memory-bandwidth-energy-wall]]에서 다룬 데이터 이동 에너지 상한을 전기 도메인이 아니라 **광 도메인으로 우회**하려는 접근이다 — 전기 신호의 pJ/bit·대역폭 밀도 상한을 광이 근본적으로 다른 물리 기구로 회피한다.

## 2. 한계 — 온도 민감성과 이종 공정 통합

미해결 문제는 네 가지다: (a) 광 소자의 온도 민감성 — 로직 발열 옆에서 파장 안정성을 유지해야 한다. (b) 광-전 결합 정렬 정밀도(sub-μm 수준). (c) 광 다이의 재작업 요구 — 광 부품은 로직 부품보다 개별 교체 요구가 크지만, [[silicon-interposer]]·[[logic-stack-hybrid-bonding]] 계열 접합 방식에서는 재작업이 근본적으로 어렵다. (d) 광 소자 제작에 필요한 이종 공정(III-V, silicon photonics, Ge photodetector)의 통합 흐름이 미성숙하다.

아키텍처 관점에서도 근본 제약이 남는다 — 광 도메인이 연산 자체에는 유리하지만, **"메모리는 여전히 전기"**라는 제약이 광 통합의 범위를 신호 전달 구간으로 한정시킨다.

## 3. 대안(비교) 후보

**Pluggable optics의 지속 개선.** CPO로 전면 전환하지 않고 기존 착탈식 광 트랜시버의 효율을 계속 개선하는 보수적 경로가, 재작업 용이성을 유지하고 싶은 세그먼트에서는 여전히 선호된다.

**Near-package optics(NPO).** CPO보다는 덜 급진적으로, 광 다이를 로직과 완전히 같은 패키지가 아니라 근접한 별도 모듈로 두는 절충안이 온도·재작업 문제를 일부 완화한다.

**AI accelerator로의 확대.** 상용화 곡선은 스위치 세그먼트에서 먼저 진행 중이지만, AI accelerator로의 확대 시점은 **논쟁 중**이다 — 스위치보다 로직 발열이 훨씬 크기 때문에 온도 민감성 문제가 더 심각해진다.

## 4. 교차 계층 영향

**아키텍처 계층에서 광 도메인 우회는 여덟 대안 후보 중 하나로 자리잡는다** — [[memory-bandwidth-energy-wall]]에서 다룬 대로, co-packaged optics는 하이퍼스케일러 수준 대역폭에서 상용화 문턱에 근접하고 있으나 시점·주도 벤더는 논쟁 중이다.

**패키징 계층에서 이종 공정 다이의 동일 패키지 통합을 강제한다** — 광-전 변환기 다이를 로직 옆에 배치하는 것은 서로 다른 공정 최적점을 갖는 다이를 하나의 패키지 안에서 봉합하도록 요구하며, 인터포저·서브스트레이트의 신호 무결성 예산이 상향돼야 한다.

**시스템·SW 계층이 패키지 내 광 통합의 조기 상용화를 요구로 되돌려보낸다** — 서빙 스택의 지연 예산이 광 인터커넥트의 패키지 내 통합을 요구하며, 이 요구는 [[hbm]]의 스택 확장 요구와 함께 패키징 계층의 로드맵 우선순위(CoWoS 캐파 확장, 광 인터포저 상용화)를 정하는 데 반영된다.
