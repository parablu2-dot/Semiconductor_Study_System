# MMMC/SSTA 사인오프

## 1. 현재 표준 — 결정론적 코너에서 통계적 조합으로

결정론적 worst-case STA로는 소자 변동성 예산을 감당하지 못한다는 판정 이후, 사인오프는 **MMMC(Multi-Mode Multi-Corner)** — process·voltage·temperature·aging·mode 조합의 수백~수천 corner를 병렬 검증하는 방식으로 재편됐다.

이 확장은 **SSTA(Statistical STA)**로 부분 대체되기도 하지만, 산업 현장에서는 SSTA가 완전히 결정론적 MMMC를 대체하지는 못했다. SSTA의 통계 모델을 파운드리가 완전히 공개·서명하지 않는 한 사인오프에 쓸 수 없다는 것이 이유이며, 이 부분은 여전히 논쟁 중이다. Liberty(.lib)의 확장인 LVF(Liberty Variation Format)와 이후의 POCV(Parametric On-Chip Variation)가 이 통계 모델을 담는 실무적 절충이다.

## 2. 한계 — 실행 시간이 설계 일정을 지배

첨단 노드에서 full-chip STA는 corner 조합·모드 조합·인스턴스 수의 곱으로 확장되며, 3 nm급 SoC의 한 번의 MMMC 사인오프 실행이 수천 코어 CPU에서 수일~수주 걸린다는 것은 산업 관찰이다(정확한 시간은 회사·설계별 편차가 크다). **결과적으로 실행 시간이 설계 반복 횟수를 제한하며, 반복 횟수 제한이 다시 아키텍처 탐색 폭을 제한한다.**

이 근원은 [[si-crystal-channel]]·[[finfet-gaa-nanosheet]]에서 다룬 소자 변동성(RDF·LER)이 노드가 내려갈수록 심해지는 데 있다 — 코너 수 자체가 아래층의 물리적 변동성 통계에서 역산된 값이므로, 사인오프 시간 문제는 방법론 층 내부의 비효율이 아니라 아래층에서 이어받은 근본 제약이다.

## 3. 대안 후보

**SSTA로의 완전 이행.** 결정론적 코너 대신 통계 분포를 직접 다루면 코너 수 폭증 문제를 근본적으로 풀 수 있지만, 파운드리가 통계 모델을 사인오프 등급으로 공개·서명하지 않는 한 산업 전체가 채택할 수 없다 — 이는 기술이 아니라 신뢰·책임 소재의 문제에 가깝다.

**Cloud-native 사인오프.** AWS·Azure·Google Cloud와 Big 3 벤더의 파트너십으로 사인오프 부하를 클라우드로 분산해 실행 시간을 압축하는 접근이다. burst capacity 확보 사례가 있지만, peak-hour 라이선스 비용·IP 보안 요구(파운드리 PDK의 클라우드 반입 조건)·데이터 egress 비용이 미해결이며, 총비용 절감 여부는 데이터가 엇갈린다.

**ML 기반 timing 예측(GNN).** 배선 전 단계에서 배선 후 타이밍을 예측해 반복 횟수를 줄이려는 시도로 MAPE 5~15% 수준의 예측 정확도가 보고되지만, 사인오프 정확도(수 ps 수준)에는 도달하지 못한다 — [[ml-eda-automation]]과 접점을 이루는 국소 최적화 사례다.

## 4. 상위/교차 계층 영향

**사인오프 실행 시간 폭증이 아키텍처 계층에 계층적(hierarchical)·타일형(tile-based) 구조를 강제한다.** flat sign-off가 시간·메모리 제약으로 불가능해지면, 아키텍처는 사인오프가 가능한 크기의 블록으로 잘려 있어야 한다 — 아키텍트는 "P&R block-sized" 단위로 기능을 파티셔닝하고, 이 경계가 캐시 뱅크·NoC 라우터·타일의 자연스러운 경계가 된다.

**코너 수 폭증이 회로·IP 계층의 IP 특성화 비용에 직접 반영된다** — [[standard-cell-ip-reuse]]에서 다룬 노드×파운드리×옵션 조합의 재특성화 부담은, 각 조합마다 이 MMMC 코너 세트 전체를 다시 검증해야 한다는 뜻이다.

**EDA 라이선스·연산 자원 비용이 진입 장벽으로 굳는다** — 첨단 노드 사인오프에 필요한 도구 스택 전체를 갖추는 데 드는 연간 라이선스는 수천만~수억 달러 수준으로 보고되며, 이는 [[open-source-eda]]가 첨단 노드에 진입하지 못하는 배경 중 하나이기도 하다.
