# 표준 셀·물리 IP 재사용

## 1. 현재 표준 — 팹리스 모델을 성립시킨 재사용 구조

표준 셀 라이브러리와 물리 IP의 재사용은 NRE(non-recurring engineering) 비용을 절감할 유일한 경로였다. 파운드리가 한 노드에서 수백 개의 표준 셀(inverter·NAND2·flip-flop 계열의 다양한 driving strength 변형)을 특성화(characterize)해 .lib 파일로 배포하면 모든 고객이 이를 공유하고, 메모리 컴파일러는 요구 사이즈에 맞춰 SRAM 매크로를 자동 생성한다. ARM·Synopsys·Cadence 같은 IP 벤더는 PCIe·DDR·USB·HBM PHY 같은 검증된 hard IP를 노드별로 공급한다.

개별 SoC 팀이 이 모든 것을 처음부터 만들 필요가 없다는 사실이 팹리스 모델 자체를 성립시켰다 — 이 재사용이 성립하지 않았다면 팹리스와 파운드리의 분업 구조도 성립하지 않았을 것이라는 해석은 통설에 가깝다. IP는 soft(RTL)·firm(합성 후 넷리스트)·hard(물리 레이아웃 확정)의 세 등급으로 유통되며, 등급이 hard에 가까울수록 성능은 검증되지만 이식성은 떨어진다.

## 2. 한계 — IP 특성화 비용의 폭증

물리 IP는 노드×파운드리×옵션 조합마다 재특성화가 필요하다. 하드 IP 하나를 새 노드로 옮기는 데 드는 엔지니어링 비용은 IP 종류에 따라 다르지만, PHY 계열의 경우 수십 인월 규모로 알려져 있다(정확한 수치는 벤더 내부 데이터이며 공개된 산업 평균은 없다). 이 비용이 벤더당 감당 가능한 노드·파운드리 조합 수를 좁혔고, **IP 벤더 생태계가 소수 대형 벤더로 집중되는 결과**를 낳았다는 관찰은 통설이다.

SRAM 밀도 개선 정체도 이 계층의 한계로 나타난다. TSMC가 공개한 노드별 SRAM 셀 면적은 5nm(0.021µm²)에서 3nm(0.0199µm²)로 약 5% 축소에 그쳤다는 것이 산업 보고에서 반복 인용되는 수치다 — [[sram-cell]]에서 다룬 소자 계층의 정체가 물리 IP 재사용 계층에서 다시 확인되는 것이다.

## 3. 대안 후보

**오픈소스 IP·PDK.** RISC-V ISA를 중심으로 SiFive·Andes·오픈소스 코어(Rocket·BOOM·CVA6)가 상용 채택을 확대했고, Google-SkyWater가 130 nm PDK를 오픈소스로 공개한 사건(2020)이 이 흐름의 상징적 계기였다. 미해결은 선단 노드 PDK는 파운드리 IP이므로 오픈소스화가 원리적으로 불가능하다는 점 — [[open-source-eda]]와 같은 한계를 공유한다.

**IP-XACT류 표준화된 배포 파이프라인.** IP 벤더·파운드리·설계 팀 사이의 view 배포·서명·감사를 표준화하려는 시도가 산업 표준으로 굳어지고 있지만, 노드×파운드리×옵션 조합의 폭증 자체를 줄이지는 못한다.

**Chiplet 단위로의 재사용 이동.** [[chiplet-ucie]] 참조 — IP 재사용의 단위를 넷리스트·레이아웃에서 아예 "물리 다이"로 옮기려는 시도로, 재특성화 비용 문제를 다른 층위(다이 간 인터페이스)로 옮기는 접근이다.

## 4. 상위 계층 영향

**IP 파편화(노드×파운드리×옵션 튜플)가 설계 방법론 계층에 IP 데이터베이스와 view 관리의 산업화를 강제한다.** 하나의 IP가 여러 노드·voltage·temperature 조합에 대해 .lib·.lef·.gds·timing model·power model 등 다중 view로 유지돼야 하며, 이 view들의 일관성 검증이 사인오프의 전제가 된다.

**IP 수 증가가 통합 검증의 지배적 지위를 강제한다** — IP 자체는 벤더가 검증했더라도, 특정 SoC에 통합됐을 때의 timing·power·전력섬·CDC/RDC·주소 맵 정합성은 통합 팀이 검증해야 하며, IP 하나를 붙이는 통합 검증 비용이 IP 라이선스 비용을 초과하는 경우가 흔하다는 관찰은 산업 통설에 가깝다.

**SRAM 밀도 정체가 아키텍처 계층으로 되돌려진다** — 캐시가 다이 면적에서 차지하는 비중이 커지는 방향으로 밀리면서, 캐시 계층 재편 압력이 [[memory-bandwidth-energy-wall]] 대응과 함께 아키텍처 계층의 의사결정으로 넘어간다.
