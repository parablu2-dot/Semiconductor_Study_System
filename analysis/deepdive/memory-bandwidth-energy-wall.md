# 메모리 대역폭·데이터 이동 에너지 이중 상한

## 1. 현재 표준(상태) — 아키텍처 계층 전체를 규정하는 두 축

이 계층의 지배적 물리 한계는 메모리 대역폭과 데이터 이동 에너지 두 축으로 요약된다. dark silicon·병렬성 천장·캐시 코히런스 트래픽 폭증·speculative execution의 보안 세금은 이 두 축의 파생물이거나 이 두 축과 얽혀서 나타난다.

**메모리 대역폭 벽(memory bandwidth wall)**은 최소 1990년대부터 지적된 문제이며(Wulf·McKee, "Hitting the Memory Wall", 1995), accelerator 시대에 더 심화됐다. HBM3/HBM3E 한 스택이 제공하는 대역폭은 약 0.8~1.2 TB/s 수준이며, 최상위 AI accelerator는 HBM 스택을 6~8개까지 붙여 수 TB/s급을 확보한다. 그러나 같은 세대의 chip-내부 tensor throughput은 수백 TFLOPS~PFLOPS급으로 성장했고, byte/FLOP 비율이 지속 악화되고 있다.

**데이터 이동 에너지 격차**는 Horowitz의 2014년 ISSCC 기조연설이 정리한 수치가 기준선이다 — 45nm 기준 32-bit ALU 연산은 약 0.1~1 pJ, on-chip SRAM 접근은 수 pJ, off-chip DRAM 접근은 수십~수백 pJ 수준. 최신 HBM은 pJ/bit를 크게 낮췄지만(대략 3~10 pJ/bit 범위로 인용됨) off-chip과 on-chip의 자릿수 격차 자체는 사라지지 않았다.

## 2. 한계 — 아키텍처 계층 내부에서 해결 불가능

**결과적으로 roofline 곡선의 대부분 영역에서 워크로드가 "memory-bound" 사분면에 걸치며, 코어를 아무리 확장해도 대역폭 상한에 부딪혀 실효 활용률이 떨어진다.** 이는 통설이며, 남는 논쟁은 이 상한을 얼마만큼 3D 스택·CIM·near-memory로 밀어낼 수 있느냐다.

**"연산을 어디에서 수행할 것인가"가 아니라 "데이터를 어디까지 이동시키지 않을 것인가"가 아키텍처의 에너지 예산을 결정한다.** 이 관찰이 지난 10년간 caches → HBM → PIM/CIM으로 이어지는 "데이터를 연산으로 옮기지 말고 연산을 데이터 쪽으로 옮기라"는 흐름의 물리적 근거다.

한 문장으로 요약하면, **이 이중 상한은 아키텍처 계층 내부에서 해결될 수 없다** — dark silicon·ILP 한계·coherence 확장 한계·speculative 보안 세금은 파생 증상으로서 완화 가능하지만, 상한 자체는 패키징·소자 계층으로 위임되어야만 밀려난다.

## 3. 대안 후보 — 상한을 넘으려는 여덟 갈래 시도

이 이중 상한을 정면 또는 우회로 넘겠다는 시도는 여덟 갈래로 나뉜다. **(i) [[compute-in-memory]]** — 데이터 이동 자체를 0에 근접시키려는 접근. **(ii) 니어 메모리 컴퓨팅(PIM)** — 삼성 HBM-PIM, SK hynix AiM, UPMEM. **(iii) [[wafer-scale-dataflow-architecture]]** — 캐시 계층을 최소화하고 정적 스케줄링으로 우회. **(iv) [[chiplet]] 기반 아키텍처 분할과 [[ucie]] 표준화** — monolithic 다이의 한계를 D2D 인터커넥트로 봉합. **(v) [[logic-stack-hybrid-bonding]]** 기반 3D 로직 스택. **(vi) 뉴로모픽·이벤트 기반 아키텍처.** **(vii) [[co-packaged-optics]]로 대표되는 광·아날로그 신호 도메인 우회.** **(viii) 명시적 스코프 병렬 모델(CUDA·SYCL·HSA류)** — [[von-neumann-cache-hierarchy]] 참조.

이 여덟 후보를 종합하면, **"메모리를 연산에 가깝게" 또는 "연산을 메모리에 가깝게" 두 방향 모두에서 실리콘·패키징·소프트웨어 스택의 재정렬이 요구되며, 어느 후보도 단독으로 이중 상한을 해결하지 못하고 여러 후보가 조합될 것**이라는 점이 현재의 산업 통설이다. 어느 조합이 지배할지는 논쟁이 남는다.

## 4. 상위 계층 영향 — 패키징에 강제하는 것

**대역폭 상한이 패키징 계층에 2.5D 인터포저와 HBM 근접 배치를 강제한다.** 폰 노이만 코어와 데이터병렬 accelerator가 요구하는 대역폭이 organic 서브스트레이트·PCB의 전기적 상한을 벗어나면, 실리콘 인터포저를 통한 short-reach·high-density 배선이 유일한 해가 된다. 오늘날 최상위 AI accelerator·데이터센터 CPU는 예외 없이 [[silicon-interposer]] 계열의 어드밴스드 패키지에 의존하며, **패키지 캐파(주로 TSMC CoWoS)가 아키텍처 실현의 병목이 되는 역방향 종속**이 발생한다 — 2023~2025년의 CoWoS 캐파 부족 국면이 이 통설을 실증했다.

**데이터 이동 에너지 상한이 패키징 계층에 하이브리드 본딩과 3D 스택을 강제한다.** on-die 인접 배선과 근접 스택의 pJ/bit 격차가 자릿수로 벌어지므로, 캐시·SRAM을 로직 다이 위에 수직으로 접는 방식([[logic-stack-hybrid-bonding]])은 선택이 아니라 필수의 방향이 된다.

**이 이중 상한이 시스템·SW 계층까지 관통해 되돌아온다** — [[mfu-utilization-gap]]에서 이론-실측 성능 격차의 대부분이 결국 이 메모리 병목에서 온다는 것이 확인되며, 시스템·SW 계층의 요구가 다시 패키징·소자 계층으로 역류하는 피드백 루프의 근원이 이 소주제다.
