# RTL 설계 흐름

## 1. 현재 표준 — 추상화가 규모를 감당한 유일한 방법

"합성 가능한 RTL(Register Transfer Level) + 표준 셀 라이브러리 + 자동 배치배선(P&R) + 정적 타이밍 분석(STA) 사인오프"가 디지털 설계의 표준 흐름이다. 1990년대 이전의 gate schematic 입력은 수십만 게이트 규모에서 이미 한계였고, 오늘날 수십억 트랜지스터 규모 SoC를 사람이 게이트 단위로 그리는 것은 물리적으로 불가능하다.

RTL이 이긴 이유는 "언제 어떤 레지스터에 어떤 값이 담기는가"라는 사이클 정확도(cycle-accurate) 수준으로만 사고하게 함으로써 설계자의 인지 부담을 관리 가능한 크기로 잘랐기 때문이다. 경쟁 후보였던 행동 수준 합성(behavioral synthesis)은 1990년대에 여러 차례 시도됐지만 QoR(면적·전력·성능) 격차를 좁히지 못해 밀렸다 — 이 경쟁의 현재형이 [[hls-high-level-synthesis]]다.

## 2. 한계 — RTL 추상화가 물리 현실과 벌어지는 격차

90 nm 이전에는 게이트 지연이 총 지연의 지배적 성분이었고, RTL 합성 후 게이트 수·게이트 유형만 봐도 최종 타이밍을 상당히 정확히 예측할 수 있었다. **7 nm 이하에서는 배선 지연이 게이트 지연을 압도**하며, 배선 지연은 물리 배치가 확정돼야만 계산된다.

결과적으로 합성 단계에서 "괜찮아 보이던" 설계가 P&R 후에 타이밍 위반으로 무너지고, 설계 팀은 합성 → P&R → 재합성의 반복 루프에 갇힌다. 이 격차를 좁히려는 physical-aware synthesis(합성 도구가 placement 추정을 내부적으로 수행)가 표준이 됐지만, 격차 자체가 사라지진 않았다는 것이 현재 인식이다.

## 3. 대안 후보

**Physical-aware synthesis의 심화.** 배치 추정을 합성 초기 단계로 더 앞당기는 방향이 계속 진행 중이지만, 근본적으로 배선 지연이 배치 확정 전에는 정확히 알 수 없다는 인과 자체는 우회할 수 없다.

**HLS로의 추상화 상승.** [[hls-high-level-synthesis]] 참조 — RTL 자체를 건너뛰고 더 높은 추상화에서 시작하려는 시도이지만, 범용 제어 로직에서는 아직 RTL을 대체하지 못한다.

**통합 플랫폼(Fusion Compiler류).** 합성·P&R·STA를 별개 단계가 아니라 하나의 데이터베이스 위에서 침투시키는 방향이 EDA 벤더 쪽 표준적 대응이다 — 세부는 [[mmmc-ssta-signoff]]와 겹친다.

## 4. 상위/교차 계층 영향

**RTL–물리 격차가 설계 방법론 계층에 흐름의 조기 물리화(shift-left)를 강제한다.** "합성 후 P&R"이라는 순차 흐름의 가정 자체가 무너지며, EDA 벤더의 제품 경계가 통합 플랫폼 방향으로 재편되도록 강제된다 — 이것이 이 소주제가 ch4(회로·IP)와 ch5(설계방법론) 양쪽에서 논의되는 이유다.

**격차 해소 실패가 검증 계층에 반복 루프 관리 부담을 강제한다** — 합성-P&R 반복이 설계 일정의 지배적 변수가 되면서, [[uvm-verification]]과 별개로 타이밍 수렴(timing closure) 자체가 검증 못지않은 시간 소모 항목이 된다.

**이 격차가 좁혀지지 않는 한, 표준 셀 라이브러리([[standard-cell-ip-reuse]])의 재특성화 요구가 노드마다 반복된다** — RTL 수준 재사용은 성립해도 물리 IP 수준 재사용이 성립하지 않는 근본 원인 중 하나가 이 추상화 격차다.
