# HBM (High Bandwidth Memory)

## 1. 현재 표준 — 메모리에서 조립 서브시스템으로

HBM은 단일 부품이 아니라 **세 계층의 결합체**다. (a) 메모리 셀 층: 삼성·SK하이닉스·마이크론이 1α~1γ nm급 공정으로 만든 DRAM 다이 4·8·12·16단 스택. (b) 패키징 층: 각 DRAM 다이 사이의 TSV로 수직 연결, 최하단 base die가 로직 인터페이스를 담당, μbump로 인터포저에 접합. (c) 인터페이스 층: JEDEC이 정의한 HBM2E·HBM3·HBM3E·HBM4의 물리·프로토콜 표준, 1024비트 폭 채널이 여러 pseudo-channel로 분할되는 구조.

**HBM의 존재 자체가 패키징 계층의 인과를 요약한다.** 아키텍처가 요구한 TB/s 대역폭·pJ/bit 효율을 organic 서브스트레이트·GDDR로는 감당할 수 없으므로, DRAM은 자기 계층의 진화 축(밀도·속도)에서 벗어나 "3D 스택 + [[silicon-interposer]] 근접 배치"라는 패키징 축의 진화에 종속됐다.

HBM4는 base die를 파운드리 로직 공정으로 이동시켜 **커스텀 base die 시대**를 여는 것으로 알려져 있다(2024~2025년 발표 기준, 최종 양산 사양은 벤더별로 확정 중). 이 "base die 커스텀화"는 HBM이 순수한 메모리 부품에서 "메모리+로직의 조립 서브시스템"으로 이동한다는 뜻이며, 이 이동 자체가 패키징 계층이 아키텍처 계층에 흡수되는 최전선이다.

## 2. 한계 — 세 계층 중 하나만 병목이어도 진화가 멈춘다

셀 층은 DRAM 커패시터 종횡비와 refresh·리텐션이 결정하고([[dram-cell-vertical-stacking]] 참조), 패키징 층은 TSV 밀도·스택 높이·열 발산이 결정하며, 인터페이스 층은 base die의 SerDes 속도와 인터포저 채널 손실이 결정한다.

**HBM 스택 내부의 열 문제는 통설과 논쟁의 경계에 있다.** 12단·16단으로 올라갈수록 상단 다이의 열 배출 경로가 길어지고, 최상단이 최하단보다 refresh 요구를 더 자주 만드는 비대칭이 발생한다는 것이 통설이다. 이 비대칭을 (a) 스택 내 온도 센서로 dynamic refresh 조정, (b) TSV 밀도 증가로 열 경로 개선, (c) 상단 다이 두께 조정 중 어느 조합으로 해결할지는 벤더별로 다르며, 어느 접근이 표준이 될지는 아직 논쟁 중이다.

## 3. 대안 후보

**Base die 커스텀화의 심화(HBM4 이후).** base die에 컨트롤러 로직뿐 아니라 [[compute-in-memory]]에서 다룬 니어 메모리 연산 유닛까지 통합하는 방향이 다음 단계로 검토되지만, 표준화된 프로그래머 인터페이스가 아직 없다.

**Hybrid bonding 기반 스택 접합.** 현재 TSV+μbump 기반 스택 접합을 [[logic-stack-hybrid-bonding]]의 Cu-Cu 직접 접합으로 대체해 스택 높이당 저항·열 저항을 낮추려는 로드맵이 있지만, 조립 후 개별 다이 재작업 불가능이라는 같은 문제를 그대로 물려받는다.

**광 인터커넥트와의 결합.** [[co-packaged-optics]]와 결합해 HBM-to-로직 구간을 넘어 로직-to-로직 구간까지 광으로 확장하려는 논의가 있지만, 아직 HBM 자체의 표준 로드맵에는 반영되지 않았다.

## 4. 상위/교차 계층 영향

**셀·패키징·인터페이스 세 계층 중 하나의 병목이 전체 세대 진화를 멈춘다는 구조가, 아키텍처 계층의 [[memory-bandwidth-energy-wall]] 대응 로드맵을 이 세 계층의 동시 진전 여부에 종속시킨다** — 대역폭 확대 요구는 셀 밀도, 스택 접합 기술, 인터페이스 SerDes 속도 세 축이 함께 움직여야만 실현된다.

**base die 커스텀화가 회로·IP 계층에 새로운 IP 카테고리(HBM base die 로직)를 만든다** — 기존 DRAM 컨트롤러 IP와 다른, 파운드리 로직 공정 기반의 메모리 인터페이스 IP가 필요해지며 이는 [[standard-cell-ip-reuse]]의 파편화 문제에 새 축을 추가한다.

**시스템·SW 계층이 스택 수·pitch 확장을 요구로 되돌려보낸다** — LLM 서빙의 KV 캐시가 HBM 용량을 압박하므로([[llm-serving-optimization]] 참조) HBM 스택 높이 확장(16-Hi 이상)과 3D 스택 밀도 향상이 요구되며, 이 요구가 다시 패키징 계층의 열·수율 한계와 충돌한다.
