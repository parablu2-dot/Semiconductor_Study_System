# 고수준 합성 (HLS)

## 1. 현재 표준(후보) — 특정 도메인의 승리, 범용은 미해결

C/C++/SystemC로 알고리즘을 기술하면 도구가 RTL을 생성하는 HLS(High-Level Synthesis)는 [[rtl-design-flow]]가 표준으로 굳은 이후에도 반복적으로 제기된 추상화 상승 시도다. Xilinx Vitis HLS·Cadence Stratus·Siemens Catapult가 상용 도구이며, **비디오 코덱·DSP·특정 가속기 도메인**에서는 채택이 실증됐다는 것이 통설이다.

## 2. 한계 — 범용 제어 로직에서의 QoR 격차

못 푼 문제는 명확하다: (a) 범용 제어 로직·저지연 회로에서 hand-written RTL과의 QoR(면적·전력·성능) 격차가 여전히 유의미하고, (b) HLS가 생성한 RTL은 디버깅·검증이 어렵고, (c) 무엇보다 아날로그·클록 도메인 크로싱·비동기 회로에는 적용되지 않는다.

**HLS가 언젠가 RTL을 대체할 것이라는 예측은 20년 넘게 반복돼 왔지만, 대체는 아직 일어나지 않았다는 점에서 논쟁 중인 사안**이다 — 이는 소극적 정체가 아니라, 데이터플로우가 명확한 도메인(영상·신호처리)과 제어가 지배적인 도메인(범용 로직) 사이의 근본적 QoR 격차가 좁혀지지 않고 있다는 뜻이다.

## 3. 대안(경쟁) 후보

**Domain-specific HLS 확대.** 범용 대체를 포기하고 DSP·영상·특정 가속기처럼 데이터플로우가 명확한 도메인에만 HLS 적용 범위를 좁히는 방향이 현재 가장 실용적인 경로로 자리잡고 있다.

**ML 기반 QoR 예측 결합.** HLS 합성 결과의 QoR을 사전에 예측해 설계 공간 탐색 속도를 높이려는 시도가 [[ml-eda-automation]]과 접점을 이루며 진행 중이지만, 이 역시 범용 제어 로직의 근본 격차를 좁히지는 못한다.

**RTL과의 하이브리드 흐름.** 제어 로직은 hand-written RTL로, 데이터패스는 HLS로 나눠 설계하는 절충이 실무에서는 이미 흔히 쓰이지만, 이는 "HLS가 RTL을 대체한다"는 원래 목표와는 다른 형태의 정착이다.

## 4. 상위/교차 계층 영향

**HLS의 도메인 국한이 설계 방법론 계층에 "도구 선택 자체가 검증 전략을 분기시킨다"는 요구를 강제한다** — HLS로 만든 블록과 hand-written RTL 블록이 같은 SoC 안에 공존하면, [[uvm-verification]] 커버리지 모델과 형식 검증 전략이 블록별로 이원화돼야 한다.

**QoR 격차가 좁혀지지 않는 한, 회로·IP 계층의 IP 재사용 전략에서 HLS 산출물은 "도메인이 검증된 IP"로만 유통된다** — 이는 [[standard-cell-ip-reuse]]가 겪는 파편화 문제에 도구 종류라는 또 하나의 분기축을 추가한다.

**ML 기반 EDA와의 결합 시도가 두 대안 후보([[hls-high-level-synthesis]], [[ml-eda-automation]])를 같은 로드맵 안에서 경쟁·보완 관계로 묶는다** — 설계 방법론 계층에서 이 둘이 독립적으로 발전할지, 하나의 통합 흐름으로 수렴할지는 아직 결정되지 않았다.
